= odds-and-sods-package-manager (opm)
:revdate: 2026-01-18

A federated, multi-language package manager with formal verification, a multi-dimensional trust pipeline, and automated ecosystem health monitoring.

== Scope

OPM wires together the hyperpolymath ecosystem into a single user-facing CLI and federation hub.

- Verification & logic: `proven` (Idris2)
- Trust pipeline: `checky-monkey`, `claim-forge`, `palimpsest-license`, `oikos`
- Manifests & ingestion: `nickel-config-reporter`, `hybrid-automation-router`, `protocol-squisher`, `scaffoldia`
- Registry & federation: `cicd-hyper-a`, `http-capability-gateway`, `git-private-farm`, Radicle, IPFS
- Bot ecosystem: `rhodibot`, `seambot`, `echidnabot`, `robot-repo-automaton`

== Federation architecture

Primary hub (opm-registry-hub) mirrors to GitHub/GitLab/Codeberg/corp.io/uni.edu plus Radicle P2P, with event propagation for:

- package-published
- security-advisory (critical, immediate, notify dependents)
- deprecation-notice
- maintainer-change
- compatibility-break

== Quick start

[source,bash]
----
# Run directly
deno task opm status

# Or install globally
deno install --allow-read --allow-env --allow-net -n opm cli/main.ts

# Then use
opm publish ./my-package
opm audit @scope/package
opm status
----

== Configuration

Config search order:

1. `$OPM_CONFIG`
2. `./opm.toml`
3. `~/.config/opm/opm.toml`

Example `opm.toml`:

[source,toml]
----
[http]
timeout_ms = 3000
retries = 2
backoff_ms = 200

[claim_forge]
base_url = "http://127.0.0.1:7001"
# token = "optional-bearer-token"

[checky_monkey]
base_url = "http://127.0.0.1:7002"

[palimpsest_license]
base_url = "http://127.0.0.1:7003"

[cicd_hyper_a]
base_url = "http://127.0.0.1:7004"

[oikos]
base_url = "http://127.0.0.1:7005"
----

== Verified code via proven

OPM uses the https://github.com/hyperpolymath/proven[proven] library for mathematically verified operations:

- **SafeUrl** - URL validation for service configurations
- **SafeJson** - Safe JSON parsing for API responses
- **Result type** - Crash-free error handling

All critical path operations use formally verified code from proven's Idris 2 core.

== Project structure

[source]
----
cli/                    # Deno CLI source
├── main.ts             # Entry point with arg parsing
├── config.ts           # Config loading (TOML)
├── http.ts             # HTTP client with retries
├── wiring.ts           # Command orchestration
├── types.ts            # TypeScript types
└── clients/            # Service client stubs
    ├── claim_forge.ts
    ├── checky_monkey.ts
    ├── palimpsest_license.ts
    ├── cicd_hyper_a.ts
    └── oikos.ts

opm-registry-hub/       # Registry hub stubs
├── schemas/            # JSON schemas
├── event-handlers/     # Event processing
└── trust-pipeline/     # Trust scoring

docs/                   # Documentation
├── architecture.adoc
└── imp/                # IMP draft specs
----

== Where to pick up

- CLI code: `cli/` (HTTP wiring stubs + tests)
- Registry hub stubs: `opm-registry-hub/` (schemas + examples)
- Architecture: `docs/architecture.adoc`
- IMP drafts: `docs/imp/`

Next work typically continues in:

- `cli/clients/*.ts` (real service contracts)
- `opm-registry-hub/` (event handlers + trust pipeline)
- `docs/imp/` (formal schema and normalization rules)
