== Status and scope

Read-only architectural baseline captured against main commit
`283ea89dca4e578a9e26a693cc9e19d4d90eee82` on 2026-11-15.
This is an evidence inventory, not a readiness certificate. The companion
link:interfaces.jsonl[JSONL inventory] is a machine-readable representation.
The proposed common operation contract is in
link:OPERATION-CONTRACT-v0.adoc[OPERATION-CONTRACT-v0.adoc].

This inventory follows link:../brief/00-MASTER-BRIEF.adoc[the master brief]
and link:../brief/03-V1-SCOPE.adoc[v1 scope]: package management is the
public centre; general remote-fleet and enterprise provisioning are deferred.
Do not conflate a file's presence, a successful Rust build, a working
integration test, or a formal proof.

Classification:

* `implemented-unverified`: substantive code exists; end-to-end claim not yet substantiated.
* `partial`: a usable route exists but contract, persistence or enforcement is incomplete.
* `scaffold`: declarations or shells exist without a demonstrated backing implementation.
* `placeholder`: route can return synthetic or success-shaped results without doing the work.
* `planned`: the integration is expressed in the design, not found in the runtime path.
* `blocked`: required execution evidence is blocked by a known failure.

== Reproducible evidence and blockers

* Main commit: `283ea89dca4e578a9e26a693cc9e19d4d90eee82`.
* Required CI: lint/test/gate fail; `proven_nif` cannot link `-lproven`.
  See issue https://github.com/hyperpolymath/odds-and-sods-package-manager/issues/135[#135]
  and workflow https://github.com/hyperpolymath/odds-and-sods-package-manager/actions/runs/42931844071[CI run].
* Rust services and TUI build jobs succeeded on that main commit; this
  is not proof of end-to-end service connectivity.
* `mix.exs` declares version `2.0.0`; Zig CLI reports `1.2.0`;
  mobile health endpoint reports `1.0.1`. Define product, protocol
  and component version fields distinctly.
* The master brief refers to `a2ml / k9` as canonical; current estate
  metadata policy and generated DEED manifests should be reconciled by
  standards owners before selecting a new canonical storage format.

== Dependency order and acceptance

. P0: restore authentic `libproven` linkage; run actual Elixir tests.
. P0: repair dry-run lockfile mutation, fake-success API responses,
  missing authorization and policy-aware trust enforcement in separate PRs.
. P1: freeze a versioned operation/capability/decision/result contract;
  each adapter advertises supported actions and failure semantics.
. P1: model durable state, idempotency, evidence, checkpoints and
  recovery across VeriSim/JanusKey boundaries; test failure injection.
. P1: unify the real CLI/API/TUI and mobile routes; maintain an explicit
  `unavailable` result for unsupplied functionality.
. P2: complete planned protocols (GraphQL/gRPC) only for demonstrated
  consumers; leave remote-fleet scope separately governed.

An interface counts as implemented only with a tested producer and
consumer, documented authorization, error handling, versioning,
observability, security policy, and evidence on the latest commit.
An architecture document alone cannot satisfy this gate.
