# Vision

OPSM exists to remove the artificial boundaries that ordinary users, developers, and administrators hit between package systems, install targets, configuration, and delivery.

A user should not need to think in terms of separate departments such as package manager, runtime manager, container manager, dev environment bootstrapper, handoff tool, archive manager, or configuration shim. The system should act like one competent manager.

## Vision statement

OPSM is the thing that gets software where it needs to go, in the form it needs to take, with the least friction and surprise.

## Design principles

- Federated by design
- Truthful about trust and limits
- Reversible by default where possible
- Target-aware, not host-only
- Bilingual: declarative and imperative
- Strict truthfulness, not strict exclusion
- Risk should degrade into safer forms, not dead ends
- One public mental model, layered internal architecture
