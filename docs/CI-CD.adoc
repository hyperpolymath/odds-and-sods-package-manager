Jonathan D.A. Jewell <j.d.a.jewell@open.ac.uk>
:toc: preamble

This document describes every automated check that runs on this repository,
what it would catch, and how to run it locally. It exists because the
repository spent months with a CI that *looked* comprehensive and gated
nothing: sixteen workflows, all red, and nobody able to say why.

== 0. The failure that made this document necessary

Every estate gate — Governance, Hypatia, Secret Scanner, OSSF Scorecard —
failed at step 1, `Set up job`, with

----
Unable to resolve action `actions/checkout@3d3c42e5…`:
invalid lockfile pin. Run `gh actions-lock` to update the lockfile
----

The message is about the *called* workflow's lockfile, not ours. A reusable
workflow is covered by the lockfile of the repository that defines it. We
pinned `metadatastician/standards` (still reachable as `hyperpolymath/standards`
by redirect) at `84355587…`, whose `actions.lock` is format `v0.0.2` and records
every dependency with the bare commit SHA as its own `ref`. GitHub's workflow
dependency lockfile enforcement rejects that shape.

Fix: pin `8e48b1caade08a552646adeab66558ac43b4360d`, whose lockfile is `v0.0.3`
and records the human-readable tag in `ref`. There is nothing a caller can do
about this class of failure except move the pin, so *when an estate reusable
fails at `Set up job`, check that repository's `actions.lock` first.*

The second failure this document records is quieter and worse: `e2e.yml` had
two Elixir jobs reading `.tool-versions` with `version-type: strict`, and that
file is generated and was never committed. Both jobs died at step 3. The suite
of ~850 tests has therefore never run in CI on this repository.

== 2. Tiers, and why "advisory" is written down

The estate's recurring CI failure is a rule with no tool behind it. The second
is an *advisory* rule that everyone reads as a gate. Every check here is
therefore one of:

*Blocking*:: a failure stops the merge. It is either a real defect or the check
  itself is broken — investigate, do not silence.
*Report-only, by policy*:: KYAML drift (Y-3 is sequenced; enforcing an
  undecided scope would be inventing policy) and JSON in any repository that
  has not finished conversion. This repository has finished, so JSON blocks.
*Advisory, temporarily*:: nothing. There is no "we will fix it later" lane.

If you add `continue-on-error: true`, say why in a comment on that step and
link the issue that removes it.

== 3. The lockfile rules you must not break

`.github/workflows/actions.lock` is machine-generated by `gh actions-lock`. It
is enforced by GitHub at job start, in the repository that defines the
workflow.

* Every `uses:` in this repository needs a `workflows` list entry and a
  `dependencies` entry.
* The dependency key is the *repository*, not the action path:
  `github/codeql-action@v4.39.1` covers `github/codeql-action/init@v4.39.1`.
* The `ref` must be the tag or branch a human can read. A bare SHA as its own
  `ref` is the defect described in §0.
* Job-level reusable workflow calls (`uses: owner/repo/.github/workflows/x.yml@ref`)
  are **not** locked — that lock lives upstream. Our wrappers still pin a full
  SHA for reproducibility, and `cicd-squabbler.yml` reports pin skew.
* After changing any `uses:`, run `gh actions-lock` and commit both halves.
  A bump without the lockfile makes every job fail with no log and no
  annotation, which is the single most expensive mistake available here.

== 4. Running the gates locally

[source,sh]
----
just ci            # everything below, in order
just ci-fast       # the cheap half: pins, formatter, JSON, YAML

just toolchain-check   # opsm.toml [runtime] vs .tool-versions vs .gitlab-ci.yml
just fmt-check         # mix format --check-formatted
just lint              # mix compile --warnings-as-errors
just test              # mix test
just proven-check      # validate test/proven_manifest.toml against the suite
just proven-report     # the suite + the coverage lattice
just json-check        # report-only; `just json-enforce` to block
just yaml-check        # parse (blocks) + KYAML drift (report-only)
just squabble-chains   # needs `squabble` on PATH
----

Tools the gates expect: `ijson-jcs` (cargo install from
hyperpolymath/ijson-jcs), `yq` ≥ 4.45 (mikefarah), `squabble` (cargo install
from hyperpolymath/cicd-squabbler), `mix`/`elixir` per `.tool-versions`.

== 5. What this repository does *not* gate, and why

* *Elixir code in `opsm-ui/`* — the directory is a vendored copy of a separate
  UI specification repository. Its nested `.github/` and `.gitlab-ci.yml` were
  removed: GitHub only reads workflows from the repository root, so those files
  could never run, and they pinned a standards commit that had already broken.
* *`opsm_ex/native/quic_transport`* — quarantined upstream of this document.
  It does not compile (h3 0.0.6 / h3-quinn 0.0.7 predate quinn 0.11's private
  `StreamId`), has no committed `Cargo.lock`, and the Elixir side falls back to
  HTTP/2 when the NIF is absent. It is excluded from the Rust matrix; see the
  header of `.gitlab-ci.yml` for the conditions for un-quarantining it.
* *Coverage percentage* — `mix test --cover` runs and reports, but no threshold
  is enforced. A threshold on a suite that has never executed in CI would be a
  guess, and a guess that fails is indistinguishable from a defect.
